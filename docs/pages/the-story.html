Design Philosophy

The Story of the Step Runner

How we moved from rigid monolithic UI generation to an agnostic, guarded, 3-dimensional pipeline with declarative-spec.

1. The Problem with Monolithic UI Builders

In traditional web libraries, generating complex UI components (such as multi-column data tables, select option matrices, or interactive form sections) is usually tightly coupled to DOM creation APIs or huge monolithic functions. If you wanted to adjust the order of colgroups, headers, or body rows, you had to rewrite loop logic, manage mutable DOM element handles, and deal with browser side-effects.

"A UI renderer should not be responsible for calculating geometry or maintaining internal transformation algorithms. It should only be an orchestrator that executes declarative blueprints step by step."

When building high-throughput JSON renderers, having the runtime know what a "table" is creates architectural friction. By decoupling instruction keys and resolving base trees via baseKey from declarative-spec, the step runner remains completely pure and domain-agnostic.

2. The 6 Generations of Architectural Evolution

The architecture of json-renderers-run-instructions-steps was continuously refined:

Version 1 — The Monolithic Step Runner

The initial step-by-step experiment. It proved that sequentially applying instruction names was vastly superior to giant functions, but it contained defensive checking bloat and coupled blueprints.

Version 2 — The 4-Line executeStep Breakthrough

Stripped away all defensive check overhead from individual steps. executeStep was reduced to a pure 4-line function: resolve instruction, dispatch dimension type, mutate destination path, and return result.

Version 3 — 2D Matrix Orchestration

Replaced custom matrix loops with json-transformer-funcs-two-dimensions (rowOnColumn and columnOnRow), establishing the tri-dimensional mathematical framework (0D, 1D, 2D).

Version 4 — Decoupled Instructions

Instruction definitions were extracted to declarative-instructions, while templates moved to spec-repo.

Version 5 — Global Browser Namespacing

Introduced automatic browser registration under window.ks.jsonRenderers.runInstructions.steps with package metadata.

Version 6 — baseKey & guardFunc Validation (Current)

Added automatic base AST resolution via baseKey from declarative-spec and comprehensive runtime verification with guardFunc to prevent malformed configurations before execution.

3. The 3D Spatial Mathematical Model

Every declarative UI element naturally lives in one of three mathematical spaces:

Dimension Nature Engine Function Example Output
0D (Primitive) Singular Object Mapping applyTemplate Cards, Badges, Form Wrapper
1D (Linear) 1-Dimensional Array Projection fromCollection Colgroups (<col>), Headers (<th>)
2D (Matrix) Cartesian Cross-Product (Row × Col) rowOnColumn / columnOnRow Table Body (<tr><td>), Select Options
